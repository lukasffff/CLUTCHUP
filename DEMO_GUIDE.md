# CLUTCHUP three-minute hackathon demonstration

This is a reproducible runbook, not a claim that the final live rehearsal has passed. Native browser control was unavailable during the audit. Do a complete desktop-browser rehearsal before presenting.

## Preparation outside the three-minute slot

1. Extract the audited build or check out the review branch. Run `node serve.cjs` (or double-click `Start CLUTCHUP.cmd`) and use desktop Chrome/Edge at `http://127.0.0.1:4174`. Keep that server open. The primary dashboard always launches one human and one AI; do not use the archived Tiny Strike page without a coach query.
2. In Settings, choose a distinct local label such as `Demo#001` and Medium graphics; Save settings. Confirm the actual laptop renderer/acceleration and input using PERFORMANCE_REPORT.md. No API key or network video is needed for the core demonstration.
3. Take a fresh **protocol v3** baseline: AI Assessment -> Run baseline -> Play vs Bots. Finish all three trials. Play naturally. The coach requires sufficient measured samples in two independent trials before calling an aim/movement/peeking weakness recurring. If it lacks evidence, collect another real baseline; do not manufacture a diagnosis or edit saved data.
4. Follow Continue through the recommended lesson. Watch the real 24-second bot demonstration, practice, and review the saved round. A failure offers support. After a supported success, return to standard conditions. Two comparable standard successes unlock challenge; challenge success offers the original three-trial reassessment. No drill configuration is needed for this normal path.
5. Complete all three reassessment trials. Verify the baseline and retest show real sample counts. If the results are unchanged or worse, explain that accurately; do not label them improvement. Training outcomes and combat randomness vary.
6. Prepare actual adaptation evidence. In repeated sessions under the same profile, side and lesson, commit to the same approach at least three times. A route preference requires continuous movement from outside the contested band, not merely spawning there. Progress should show the approach counts. A real changed route/hold choice must appear in the decision log; compare its previous and selected plan. A reaction-delay change alone is not tactical evidence.
7. Optional controlled comparison: Progress -> Play fixed comparison and Play adaptive comparison. Alternate fixed/adaptive order and play at least two rounds in each, preferably more. Both use the same customs starts, controller, pistols, no buying and reaction delay. The fixed condition disables historical route/peek choices while retaining reactive combat/abilities. Results remain descriptive; this is not a controlled human-learning study. Do not substitute test-fixture records for player data.
8. Prepare two browser tabs: A = Progress with the real baseline/retest and decision log ready to expand; B = the recommended training launch, agent selected and Play vs Bots ready. Keep an additional report tab only if useful. Pre-recorded results shown in the slot must be identified as **this player's rehearsal results**. They are not generated in the following 30-second results segment.
9. Run one full timed rehearsal. Test mouse capture, WASD, firing, R reload, Ctrl crouch, Space jump, F objective use, V last weapon, and C/Q/E/X abilities. Confirm only one opponent. Confirm the server works offline. Have a local copy of the reports/runbook ready. Do not claim readiness if this fails.

| Time | Presenter action | What to say/show |

| 0:00-0:25 | Tab A, homepage then Progress. | "CLUTCHUP turns a solo tactical duel into a measurable coaching loop. Fixed bots repeat a challenge; this coach selects authored tactics and lessons from your recorded play." Explain the player problem without claiming machine learning. |
| 0:25-0:50 | Expand the genuine rehearsal baseline and recommendation. Show the raw counts and three-trial protocol. | State the recorded action, the evidence count, why it might hurt the player, and the selected correction. Call a weakness recurring only when the report supports it. |

| 1:15-2:10 | Play the live 1v1. Use the correction rather than chasing a win. If a round ends early, show its measured feedback and Continue to retry. | Point out a tactical adaptation only if the decision log confirms a changed route/watch/position. | 2:10-2:40 | Tab A: refresh Progress. Show the new practice result, then expand the already recorded v3 rehearsal baseline/retest pair and decision log. | Explicitly identify which results were collected before the slot. | 2:40-3:00 | Show the fixed/adaptive comparison card or its honest empty state. | Separate observed behavior, the coach's inference, what the bot changed, measured player change and uncertainty. ## Presenter language and fallbacks

- Supported: "Eight of ten shots in these trials were moving shots" **only if those are the real displayed counts**. Never copy example numbers into the demo as results.
- Supported: "The selected route changed based on three recorded approaches" only when the route/log actually changed. The automated audit verifies the code can change route coordinates; that is not itself a player's live adaptation result.
- Avoid: "The AI learned a new strategy," "this proves coaching caused improvement," or "all agents have been visually playtested." Tactics are predefined and selected by rules. Ability logic has automated coverage; physical key feel and visuals need rehearsal.
- If the browser refuses pointer lock, use desktop Edge/Chrome and click the game. If it still fails, stop live input, show the saved genuine report, and disclose the problem. Do not use a fake gameplay recording.
- If no supported weakness exists, explain the insufficient-data outcome and use an explicitly labelled Academy practice lesson. Do not portray that manual fallback as automatic diagnosis.
- If no retest exists, show the real baseline/practice counts and state reassessment is pending. Do not produce a synthetic before/after slide.
- If YouTube is blocked or a provider key is unavailable, keep the core offline duel demo. Video analysis is optional: YouTube offers manual notes, while authorized local footage can send sampled images to a configured provider. Live model quality was not verified in this audit.
